# Selected phase snapshots

A before judgment must remain recoverable after a genuine correction changes
the selected Claim, approved personal state, or personality checkpoint. FloRA
freezes an experiment read route for each case, phase and native arm. Production
heads keep advancing. A snapshot never rewinds them or freezes permission.

This is infrastructure for the [experiment goal](EXPERIMENT_GOAL.md), not a new
model, learned memory substitute, independent judge, or successful experiment.

## What the route preserves

| Component | Pinned record | Authority still checked on use |
| --- | --- | --- |
| Claim | Exact projection, immutable version and evidence relations | Matching actual XTDB history; immutable full records; present quarantine and source permission |
| Personal state | Active version, activation receipt and approval event | Actual immutable version/activation; independently enrolled owner proof; live control and source permission |
| Episode | Accepted publication and thread head | Actual immutable publication, independent admission and current source/control authority |
| Producer role | Exact admitted MFM and personality manifests | Actual historical checkpoint bytes, immutable admission/qualification and independent producer verification |
| Phase context | Finite Claim/state routes, delivered hashes and original source closure | Rebuilt actual selected context and separately authorized original phase history |

`SelectedPhaseRoute` rebuilds the actual governed readers around those pins. It
does not treat cached context as authority. The runtime checks that its Claim,
state, context policy, admission service and artifact readers share the exact
bound services. Read routes reject formation, admission, activation and other
production writes.

Vector or graph retrieval may nominate candidates before freezing. The frozen
plan must name exact selected records; rerunning a mutable accelerator cannot
prove what a before context contained.

## Capture and recovery

`XTDBPhaseSnapshotCustody.capture(...)` requires an actual selected runtime,
original phase history and `NativeJudgmentLineageVerifier`. Current personal
source/control permission and independent evaluation consent are checked before
the first private read, throughout context/proof reads and before return.

The private encrypted manifest includes actual role qualifications and opaque
producer phase receipts. The producer's adapter must independently authenticate
the actual training/update export and its exclusion for that phase. A structurally
valid export or manifest does not qualify a model or prove no future leakage.

A metadata-only XTDB capture intent binds the exact body hash, Claim IDs, source
closure, context hashes and canonical event material. The phase event binds the
intent hash. The manifest then has a canonical Kurrent event, registered encrypted
source and immutable XTDB custody index.

Capture creates **no grants**. Using the new artifact needs independently granted
current `personal_judgment` permission on the artifact and its ancestor closure,
plus current evaluation consent for the original phase history. Both before and
after routes stop when source permission or Claim availability is withdrawn.
The phase artifact is internal; it cannot join shared original history or be
opened through a generic comparison reader.

Archive custody binds its own `artifact_permissions` to the actual owner policy
on the same selected registry and connection. Native original-only context
guards may deny every phase/manifest artifact without blocking authorized
archive recovery. This custody permission route is limited by the exact intent,
event and snapshot metadata; it grants no internal artifact model membership.

`recover(...)` authenticates the private manifest through those current gates.
`SelectedPhaseRoute(..., historical_bindings=...)` then requires the actual
checkpoint files and producer adapters for that phase. A different after model
cannot stand in for a missing before checkpoint.

`check_live()` is a metadata/current-permission fence. It does not reread the
snapshot plaintext on every nested read. Actual context and model use still
revalidate immutable selected records, current authority and producer proofs.

## Same-evidence ablation

Before the intervention, both native arms use the `full_update` policy: there is
no future correction to claim as withheld. The after full arm keeps that policy.
The after ablation must bind the actual before full snapshot, exact canonical
update event IDs and an independently verified producer exclusion receipt.

The actual personality qualifier supplies
`verify_phase_update_policy(request=..., receipt=...)`. Its result must bind the
run, case, phase, arm, original history, context lineage, policy and exact admitted
artifact. Missing or mismatched producer semantics block the ablation. The
qualified phase lineage rechecks this proof on each context qualification;
FloRA supplies no implementation that invents an exclusion.

## Interrupted capture

Passive recovery performs no index repair. Reusing a partially captured snapshot
ID also fails; it cannot reinterpret that ID after production advances.

`reconcile(...)` is a separate explicit write route for an already committed
capture whose final XTDB index is missing. It requires the exact durable intent,
canonical event, registered source/raw binding, current independently granted
permission, original evaluation authority and actual selected/producer/owner
qualification. It writes only the missing index and appends no event. Moved
Claim, state, episode or producer heads stop repair instead of recapturing them.

If source registration, owner grant or the canonical append itself is missing,
repair stays blocked. Independent registration/enrollment routes must supply
their own authority; reconciliation does not invent it. The durable intent
remains visible for diagnosis.

## Integration boundary

Native entries select a typed `NativePhaseSnapshotBinding` for their exact
case/phase/arm. Bind **both** `route.runtime` and `route.lineage`, and use the exact
`route.snapshot.plan`. Keep `SelectedRunEvidencePolicy` as the live authority for
original history. A metadata reference alone is insufficient.

`SelectedPhaseLineageRouter` binds the complete native case/phase/arm matrix to
actual frozen native arm headers and actual selected evaluation authority on the
same connection. Its header names predeclared snapshot IDs so it creates no
run-plan/content-hash cycle. The router's record/digest describes configuration;
it is not model, worker or experiment qualification.

Every router use opens a fresh actual phase route and checks its exact context
plan, context bytes, checkpoint and native header lineage. Result verification
derives the invocation ID from that arm's frozen entry and recovers the actual
qualified execution with repair disabled. Full and ablation arms therefore have
their own exact execution records; a shared case/phase resolver cannot substitute
one arm's output for another.

Lifecycle recognition uses a typed `PhaseSnapshotReference` and
`recognize_phase_snapshot(...)`: exact registered
event/hash matching, actual historical selected records, current source/evaluation
permission and producer proofs. Permission/proof tail entries require their own
actual canonical verification; there is no event-type allowance.

## Remaining genuine-intervention blocker

Current custody requires the final paired run-plan digest before capturing a
snapshot. That digest contains both native arm headers, including the actual
after context hash and personality checkpoint hash. A real before capture
cannot know those future learned values. The mechanical fixtures use supplied
bytes known in advance; they do not solve this workflow.

The next required step is a two-stage capture contract:

1. Preregister an immutable anchor for the protocol, questions, original-history
   policy, budgets and arm contracts, before intervention or evaluation.
2. Capture actual before authority and producer/source proofs against that
   anchor, without predicting an after checkpoint or context.
3. Perform the actual governed intervention, then capture its after authority.
4. Seal the observed phase binding matrix and exact earlier anchor/snapshot
   references into the final paired plan before evaluation. Budgets and held-out
   boundaries remain those preregistered in the anchor.

This contract is not implemented here. Its producer receipts and final-plan
link checks must authenticate the actual prior captures; a new identifier or
shape-valid anchor cannot substitute for those proofs. Until that route exists,
these files establish historical custody and strict replay mechanics, not a
ready genuine before/train/after experiment.

## Verification boundary

Unit checks use fictional signed producer receipts and SQL contracts. They cover
historical pinning, live withdrawal before private I/O, missing checkpoint bytes,
typed lifecycle recognition, withheld-update requirements, canonical intent
binding and explicit missing-index repair. They establish mechanical behavior.

`tests/integration/test_selected_phase_history_routes.py` exercises actual
Kurrent/XTDB/encrypted-object storage: an interrupted index write, independently
signed artifact permission, reconciliation without append, genuine Claim/state/
checkpoint replacement, before/after reconstruction and live withdrawal. A
second gate binds all four native routes and distinct actual qualified execution
records through the strict router, including arm-substitution rejection and
after-ablation update-exclusion proof. Passive replay invokes no inference and
appends no canonical event. Denial spies observe actual ciphertext backend reads.

Its producer bytes, signed receipts, supplied outputs and counters are explicitly
fictional. The selected backend gate is pending; neither test lane demonstrates
learned judgment, the two-stage capture workflow, or consumer readiness.
