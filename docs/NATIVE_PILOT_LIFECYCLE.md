# Native synthetic-pilot transition

`selected/pilot_lifecycle.py` connects the fictional pilot intake to a genuine
selected-runtime **before judgment**, then appends the correction or outcome.
It contains no MFM, personality model, learning rule, substitute verdict, score,
threshold, or automatic authority grant.

## Supplied-services entry point

1. `materialize_before` from the existing pilot intake creates the exact
   fictional original prefix on an empty, isolated case stream. Register those
   originals and obtain the actual scoped formation/judgment permissions through
   the existing selected services. These permission records stay outside the
   shared original history.
2. A qualified external producer executes formation, independent Claim
   adjudication, governed state/episode construction as needed, and native
   judgment. Inference belongs to the separately terminable qualified worker
   route. Return `NativeBeforeReference` with exact formation request/bundle/run
   IDs, the context plan, actual task bytes and judgment invocation ID.
3. `verify_native_before` independently recovers the actual formation and
   judgment using `reconcile=False`. Missing private indexes stop rather than
   trigger repair. The actual native lineage service checks the original-only
   history, current Claims/state/episode authority and externally qualified phase
   exclusion receipts. Current scoped permissions remain required.
4. The lifecycle verifies every remaining canonical event through its actual
   typed service: current governed projection/publication, private candidate or
   approval custody, applied current permission, and durable owner proof signed
   by the runtime's previously enrolled key. The entire canonical prefix is
   frozen. An otherwise genuine decision does not authorize an arbitrary extra
   observation, unqualified proposal, provisional state or unrelated control.
   Unsupported receipts stop; event names alone confer no authority.
5. `apply_native_intervention` redoes that independent recovery, appends the
   fictional original intervention, and returns `NativePilotTransition`.
   Alternatively, `await run_native_pilot_transition(...)` awaits the supplied
   before executor and carries out the same verified transition.

`NativeBeforeReference.phase_snapshots` may also name already captured, typed
`PhaseSnapshotReference` records. Supply `NativePilotPhaseSnapshotServices` with
their actual selected custody, exact archived role bindings by snapshot ID and
independent invocation lookup. The lifecycle recognizes only exact before-phase
references for this case and run through `recognize_phase_snapshot`; it also
recovers their current use grants and durable enrolled owner proofs. A snapshot
event name alone grants no authority. Its canonical record and controls join the
validated tail, while its ID remains outside original user history. This helper
does not silently capture a snapshot, select a checkpoint or create its grants.

The returned after `HistorySnapshot` is the exact original before prefix plus
one original intervention. Native outputs, approvals, permissions, artifacts
and model receipts remain canonical audit records, not baseline input history.
The caller must register/authorize the new original before subsequent formation;
intake never silently grants processing, training, evaluation or API disclosure.

## Historical time and actual causal order

The public pilot is a fictional historical scenario. Its `observed_at` remains
in the new structured intervention payload together with the exact source ID,
kind and original text. The canonical intervention event uses the supplied
current causal time, after the real native before run. Kurrent supplies physical
commit time; this helper never backdates it.

For an outcome, the original observation has no native decision parent. A
separate synthetic `outcome` audit event links both the native before decision
and the new original observation. That audit is excluded from shared history.
Its `causal_claim` is explicitly `none`: a fictional trial story does not prove
that someone followed the native advice, that the advice caused the observation,
or that the judgment was good. The historical story and actual experiment
execution time are distinct.

Appends are separate Kurrent commits. If the outcome-audit append fails after
the original append, the original remains a retained partial intake; this is not
a global transaction or an automatic replay/reset operation. A repeated
transition refuses the changed canonical tail. Inspect/reconcile the actual
partial intake explicitly rather than duplicating the intervention.

Current original-source and phase permission are checked after slow metadata or
payload writes and immediately before every canonical append. They are checked
again after the commit before accepting the transition. A withdrawal can stop
the audit or acceptance while an already committed original remains retained.
That is partial intake requiring explicit inspection/reconciliation, not a
returned complete transition or an automatic rollback.

## Boundary this does not close

This milestone solves **native before recovery → original intervention intake**
and allows explicitly qualified phase snapshots to participate in the verified
before tail. Archived before/after routing belongs to the separate phase custody
and selected-route components; this lifecycle does not itself choose or create
those routes. Real producer bindings, phase exclusion proofs and current source
consent are still required before recovering both phases after an update and
scoring the full paired run.

The same-evidence withheld-update arm also requires an actual producer export
and update-exclusion proof. It must receive the same evidence while excluding
the targeted personal judgment update; a general API with the same prompt is
not that ablation. These exports/proofs belong to the model workstreams. This
chat prepares infrastructure and will plug them in when qualified.

Eight local tests verify only causal/append mechanics, original/control
separation, historical metadata, refusal of generic/text-only substitutes and
current authority across slow metadata, payload and commit boundaries.
The unique selected-backend test exercises real original intake, durable
permissions/proofs, formation/admission/state/native recovery, strict tail
coverage, typed snapshot/grant/proof participation, private-read withdrawal and
outcome separation with **fictional supplied producer outputs**.
It must pass on the selected engines before the new lifecycle is backend
qualified. Neither test is a learned result or a benchmark win.
