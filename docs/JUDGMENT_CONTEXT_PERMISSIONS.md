# Current judgment context permissions

Retrieval nominates source metadata before any original content is opened. Exact Claim, Qdrant and Ladybug formation routes use canonical Claim/Event manifests; the upstream registered formation store then checks permission and opens original bytes. Graph reachability cannot grant plaintext access.

`RegisteredJudgmentContextPolicy` binds one host and authority namespace to the selected source registry, current permission heads, Claim authority and governed personal state. A `memory_formation` grant does not authorize `personal_judgment` or external provider disclosure. Original events and their parent closure must match canonical Kurrent records. An active state additionally needs its exact activation receipt and a registered, purpose-permitted approval event; the state reader still verifies the independent approval signature.

The context assembler checks each original's permission before and after plaintext reads and checks materialized Claim/state heads again before returning. Delivery and decision recording reapply the current checks. A late denial can leave an encrypted, unusable intermediate object; this is not an atomic transaction across engines, erasure, or removal from already-running model state.

The policy supplies no learned planner, semantic sufficiency test, MFM or personality model. Explicit route plans and declared minimum counts remain visible reference inputs. Episode-source use is refused until the selected accepted-episode closure is connected. The primitive source reader still allows a caller to omit its optional authorizer for narrower custody verification; live judgment must use the governed context path.

Seven source-use, five formation-route and four judgment-policy boundary tests pass. Actual selected-backend integration remains a separate gate; these fixture checks do not establish learned behavior.
