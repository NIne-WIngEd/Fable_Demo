# Context delivery and evidence receipt

The Context Planner eventually chooses what Fable needs for a situation. FloRA currently implements the **model-independent assembly boundary**. An explicit `ContextPlan` selects exact claims, approved host/relationship/self state, and optionally Qdrant vector or LadybugDB evidence-graph candidates. It uses the selected XTDB, KurrentDB, encrypted object, Qdrant, and LadybugDB paths. A trusted local policy adapter must permit every claim, state, source event, and approval event for the declared purpose.

The returned `LocalContext` contains the authoritative claim value with exact raw source content and the approved state bytes. It stays local. Before a verdict is recorded, an Experience `context_delivery` event stores a private receipt with source IDs, claim and state versions, approval event IDs, and content digests. It stores no duplicate context plaintext. The receipt is rechecked against current authority and permissions at delivery and at the decision boundary. A supplied verdict is linked to that receipt and source events. If the declared evidence count is not met, the contextual decision path defers.

**What this proves:** the selected material was assembled, allowed, and delivered to a decision interface at a particular time. It does not prove a model read or attended to it, that the chosen items were semantically relevant, or that the verdict was caused by personal state. The explicit plan and synthetic test policy are not a learned Context Planner or a production authorization service. Adaptive planning, semantic sufficiency, latency qualification, and intervention tests await their own work and the qualified personality model.
