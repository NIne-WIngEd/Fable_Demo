# Two-stage FloRA experiment registration

This connects the prepared synthetic experiment to actual selected custody before the AFTER checkpoints exist. It does not train personality, MFM or FBM; qualify a behavioral result; supply targets; or invent a success threshold.

The first immutable document is an **anchor**, not a final `PairedRunPlan`. It fixes the actual cohort and limited-builder recipe, prepared histories and shared questions, supplied protocol and budgets, producer/worker/comparator contracts, known baseline role nominations, selection and update policies, and every capture, update, probe, evaluation and provider-task identity. It excludes unknown AFTER checkpoint, selected-context and result hashes.

## The lifecycle

| Stage | Actual evidence required | Result |
|---|---|---|
| Register | Current registered cohort/recipe and exact original history/question sources | Canonical encrypted anchor |
| Register originals | Actual typed anchor and independently allowed capture purpose | History/question custody without a final plan |
| Capture BEFORE | Actual selected phase route, original-source authority and independent producer qualifications | One immutable capture per declared native slot |
| Seal BEFORE | All declared BEFORE captures and exact qualified baseline nominations | Canonical before seal, preceding treatment |
| Authorize update | Actual before seal and frozen update contract/IDs | Producer authorization marker; no learning claim |
| Record update | Post-gate canonical execution/activation receipts and independent opaque producer proof | Actual authorized update receipt |
| Capture AFTER | Actual updated selected authority; retained-personality exclusion proof for ablation | Declared AFTER capture slots |
| Finalize | Entire table, actual historical checkpoints/contexts, current qualifications and no prior paired evaluation | Single final binding plus derived native/paired plans |
| Execute | Actual final authority and separately qualified native/provider services | Paired attempt custody; no automatic Part1 acceptance |

The finalizer takes no caller-selected subset. It derives the complete native plans and `PairedRunPlan` v3 from actual qualified captures. Captures bind the earlier anchor; the later final plan can include their observed hashes. The final seal links both and is never hashed back into the plan. BEFORE probes use distinct identities from final paired evaluation.

AFTER producer ports can be enrolled **after** their actual checkpoint files exist. `bind_phase_custody` accepts an empty or BEFORE-only map; `bind_historical_bindings` enrolls each actual `RuntimeRoleBinding` pair once. Recovery checks their actual checkpoints and frozen input/output/qualifier contracts. No fictitious future path, checkpoint bytes, digest, head rewind or producer is required to seal BEFORE.

## Concrete controllers

`XTDBExperimentPreregistrationCustody` requires the actual co-located comparison and manifest controllers, registered source registry, Kurrent log, encrypted object plane, owner permission service, scope and namespace. It writes private `preregistration_*` controls through encrypted objects and canonical append before the XTDB index. The durable anchor is `artifact_id="preregistration"`; the final seal is `artifact_id="final_binding"`.

The public sequence is:

1. `register(spec=..., histories=..., questions=...)`.
2. After current owner capture/read permissions exist, `register_original_inputs(occurred_at=...)`.
3. Bind actual phase custody and currently available historical producer ports. Capture through that custody, then `publish_capture(snapshot_id=...)` for every BEFORE slot.
4. `seal_before()`, then `begin_update()` **before** actual producer execution.
5. Supply actual canonical execution/activation receipts and independently authenticated producer proofs to `record_update(...)`. A metadata marker alone cannot prove an update.
6. Enroll available AFTER ports; capture and publish every AFTER slot.
7. `finalize()`, then after explicit final-control permission, `register_final_inputs(final_authority=..., occurred_at=...)`.
8. Supply that actual final authority to the coordinator, selected evidence policy and native/provider adapters.

No controller creates grants. Source, manifest/control read, capture, evaluation and external-transfer purposes remain separate. Generic comparison readers reject these private controls; only exact dedicated recovery opens them.

## Current authority and recovery

Own-source and foreign cohort dependency checks run before and after raw operations, including the actual inner ciphertext-fetch/AEAD boundary and immediately before canonical append after slow revision/dependency work. Existing authority is never a lease for the next boundary.

One `_current` call shares only its actual selected source/raw/action/head row observations and decoded canonical commits. Every original gate and permission callback still runs. After those callbacks, a fresh canonical replay and the exact terminal current-row fence recheck the observations. Pure reader and predicate identity checks follow all fresh replays and each terminal SQL read, so a callback cannot replace the actual reader while returning unchanged evidence. The scope ends on return, before the next private backend boundary; producer, update and exclusion qualifications are never cached by this sampler.

The metadata-only `_authorize_slot` operation can share these observations across its two unchanged `_current` predicate bodies. Eligibility requires exact selected controller types and unchanged transitive readers, wrapped helpers, decoders, scope methods and typed input fields. Custom readers use the existing uncached route from the start; a late binding change denies. The frame closes before the final actual canonical replay, which rechecks stage/update and evaluation-absence evidence, then one finite SQL statement rechecks every observed source/raw/head/action and manifest/control/provider key. Control/provider absence is checked by exact key without filtering away a wrong-scope row. Pure binding checks follow this final statement. The frame never surrounds ciphertext reads, producer/update/exclusion qualification or a private source callback, and supplies no authority for the next operation.

The typed controlled-transport regression retains both `_current` calls, both predicate bodies and all 70 source-gate callbacks while reducing one BEFORE slot authorization from 52 to 25 SQL reads and 11 to 2 actual canonical replays. Signed owner withdrawal after the last metadata callback, new canonical stage/evaluation markers without indexes, newly present provider keys in either scope, and late reader/namespace/input changes all deny. These counts qualify this bounded infrastructure change; they do not establish physical latency or capture completion.

`authorize_plan(metadata_only=True)` and `require_evaluation(...)` authenticate the exact final payload digest, complete immutable slot metadata and current source/control authority without opening producer proofs. Outer `authorize_evaluation(...)` independently requalifies actual stored update and historical capture proofs before dispatch and result acceptance. Typed class construction itself is insufficient: the complete candidate plan/native maps must match the actual sealed canonical payload.

`authorize_attempt_capture(...)` is narrower: it authenticates the exact final provider task and current manifest/custody dependency closure for an **already observed signed call**, while the ledger separately checks local capture or audit consent. Evaluation or external permission withdrawal cannot erase that observed denominator. This helper cannot dispatch a call or accept its output.

`bind_read_connection` uses an actual owned SELECT-only connection. Without separately initialized actual phase/producer services, it supplies metadata guards only. Full proof authorization requires the explicit actual phase controller and complete historical producer ports; it never guesses how to clone codecs or a model. Separately located source backends require their own owned readers.

An append followed by a failed index write stays incomplete. Later stages and passive recovery stop. Explicit `register(..., reconcile=True)`, `reconcile_slot`, or the corresponding stage `reconcile=True` operation authenticates the same frozen body and canonical parents before repairing only the missing index; it cannot recapture, rerun, overwrite or append a replacement. `recover_final_binding()` is passive and checks the actual current sealed binding.
